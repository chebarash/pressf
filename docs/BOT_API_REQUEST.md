# Запрос к боту: API для Press F

Запрос от сайта Press F к боту (репозиторий `anonymous`). Это продолжение
`anonymous/docs/SITE_INTEGRATION.md`: там контракт из четырёх эндпоинтов, здесь он
уточнён и расширен под новый дизайн.

Что меняется: Press F перестаёт быть только рейтингом и становится гидом по NewUU.
Школы, программы, курикулум, расписание группы, упоминания из канала. Отзывов и
комментариев на сайте больше нет, текстовые мнения идут только через упоминания.

Дизайн: https://www.figma.com/design/FmLDCU6LOFiYBhkwelL1B5/Press-F (страница
`05 Motion & Data` показывает, откуда какая секция берёт данные).

## Общие правила

- Все эндпоинты `GET`, read-only, JSON, на том же aiohttp (`anonymous/web.py`).
- Авторизация: сервисный токен в заголовке `Authorization: Bearer <token>`. Без
  токена `401`. Значение токена берётся из конфига, не из кода.
- Сайт забирает данные по расписанию раз в сутки и кеширует у себя, поэтому на
  пользовательские запросы API не отвечает.
- Бот не обращается к сайту по сети и работает, когда сайт лежит. Единственное, что
  он теперь знает о сайте, это схема ссылок из раздела «Ссылки на сайт в ответах».
- **Стабильные id обязательны.** Сайт привязывает к ним оценки студентов, так что
  id не должен меняться при пересборке справочника:
  - преподаватель: `id` (slug или хеш от нормализованного имени + email);
  - курс: `code` в нормализованном виде (`MATH 211` и `MATH211` это один `MATH211`).
- Каждый ответ-список содержит время актуальности данных, чтобы сайт мог показать
  «данные от 31 октября», если источник недоступен:

```json
{ "updated_at": "2026-10-31T03:00:00Z", "items": [] }
```

Формат элементов ниже описан для `items`.

## Приоритеты

- **P0:** `/api/faculty`, `/api/courses`, `/api/timetable`, `/api/groups`,
  `/api/semesters`. Без них не работают страницы и «Мой семестр».
- **P1:** `/api/schools`, `/api/programs/{slug}/curriculum`.
- **P1:** ссылки на сайт в ответах бота. Нужны стабильные id из P0.
- **P2:** `/api/mentions`. Блокеров нет, просто идёт после данных для страниц.

## Эндпоинты

### P0

```
GET /api/faculty
```

```json
{
  "id": "goncalo-pinto",
  "name": "Gonçalo Pinto",
  "position": "Assistant Professor",
  "department": "Mathematics",
  "school": "humanities",
  "email": "g.pinto@newuu.uz",
  "office": "B-312",
  "photo_url": "https://...",
  "url": "https://newuu.uz/en/employee/...",
  "teaches": ["MATH111", "MATH211"]
}
```

- `department`, `office`, `school`, `photo_url` могут быть `null`: кабинет и кафедра
  есть только у 112 из 236, и сайт это учитывает.
- `photo_url` нужен, чтобы нарисовать лицо. Где фото нет, сайт покажет дефолтное.
- `teaches` идёт из сетки занятий. У тех, кто в сетке, но не в справочнике, запись
  всё равно нужна, с теми полями, что известны.

```
GET /api/courses
```

```json
{
  "code": "MATH111",
  "subject": "Calculus 1",
  "aliases": ["Calculus I", "калкулус 1"],
  "teachers": ["goncalo-pinto"],
  "classes": ["FCS 1", "FCS 2"]
}
```

`teachers` содержит `id` из `/api/faculty`, а не строки имён.

```
GET /api/timetable?class=FCS%201
```

Также `?teacher=<id>`, `?code=`, `?room=`.

```json
{
  "class": "FCS 1",
  "day": 0,
  "starts": "10:00",
  "ends": "11:20",
  "subject": "Calculus 1",
  "code": "MATH111",
  "teacher": "goncalo-pinto",
  "teacher_name": "Gonçalo Pinto",
  "room": "B-204"
}
```

`day`: 0 это понедельник, как в таблице `timetable`.

```
GET /api/groups
```

Нужен для выбора группы и связи группы с программой и годом.

```json
{ "class": "FCS 1", "program": "software-engineering", "year": 1 }
```

`program` и `year` могут быть `null`, если из названия потока их не вывести.
Сопоставление поток → программа это как раз вопрос к боту: опишите, как оно
получается, и какие потоки остаются без программы.

```
GET /api/semesters
```

Нужен для подсказки «посмотри курсы на следующий семестр» в последние недели
семестра.

```json
{
  "current": { "id": "fall-2026", "name": "Fall 2026", "starts": "2026-09-07", "ends": "2027-01-15" },
  "next": { "id": "spring-2027", "name": "Spring 2027", "starts": "2027-02-01", "ends": "2027-06-11" }
}
```

Если дат нет в источниках, достаточно настройки в конфиге бота, обновляемой вручную.

### P1

```
GET /api/schools
```

```json
{
  "slug": "computing",
  "name": "School of Computing",
  "programs": [
    { "slug": "software-engineering", "name": "Software Engineering", "degree": "B.Sc." }
  ]
}
```

На `newuu.uz/en/undergraduate-program` сейчас 5 школ и 10 программ, при этом на
главной написано 9 программ. Отдавайте то, что реально есть в источнике.

```
GET /api/programs/{slug}/curriculum
```

```json
{
  "program": "software-engineering",
  "source_url": "https://...",
  "academic_year": "2026-2027",
  "semesters": [
    {
      "number": 1,
      "year": 1,
      "term": "fall",
      "courses": [
        {
          "code": "MATH111",
          "subject": "Calculus 1",
          "credits": 6,
          "type": "core",
          "elective_group": null,
          "prerequisites": ["MATH101"]
        }
      ]
    }
  ]
}
```

- `type`: `core` или `elective`. Выборные из одной группы имеют общий `elective_group`.
- `credits` и `prerequisites` могут быть `null` или `[]`, если их нет в источнике.
  Выдумывать и выводить их моделью не нужно: неверный prerequisite хуже пустого.
- Обратная связь «что открывает курс» считается на сайте из `prerequisites`.
- `source_url` обязателен: откуда взяты данные.

Откуда брать: PDF и страницы `newuu.uz`, которые уже обходит `site_chunks`.
Посмотрите, что там реально есть, и напишите, для каких программ курикулум
доступен, а для каких нет.

### P2

```
GET /api/mentions?code=MATH111&limit=50&offset=0
GET /api/mentions?teacher=<id>&limit=50&offset=0
GET /api/mentions?codes=MATH111,PHYS111&limit=20
GET /api/mentions?limit=20
```

```json
{
  "post_id": 12345,
  "url": "https://t.me/...",
  "text": "сниппет до 500 символов",
  "date": "2026-03-12T10:21:00Z",
  "matched": "code",
  "query": "MATH111"
}
```

- Сопоставление то же, что в `people.py` и `timetable.py`, заново его не пишем.
- `codes` нужен для «Мой семестр»: посты сразу по всем курсам студента.
- Без параметров это свежая лента для главной.
- На верхнем уровне ответа нужен `total`: сайт показывает счётчик постов на вкладке.
- Авторов нет и быть не должно. `text` только из того, что уже опубликовано в канале.

## Ссылки на сайт в ответах

Если вопрос автора связан с курсом, преподавателем, группой или программой, бот
подсказывает автору, что это есть на Press F, и по возможности даёт прямую ссылку на
нужную страницу. Подсказка дополняет обычный ответ и ничего не меняет в маршруте
вопроса.

### Включение

Новая настройка `PRESSF_BASE_URL`, пустое значение выключает фичу целиком, как
`SITE_BASE_URL` выключает обход. Имя другое, потому что `SITE_BASE_URL` уже занят под
newuu.uz. Значение на проде: `https://pressf.chebarash.uz`, но его задаём только после выкатки
новых страниц: иначе бот будет раздавать ссылки в 404.

### Схема ссылок

Сайт обязуется держать эти адреса стабильными:

| что совпало | ссылка |
|---|---|
| код или название курса | `{PRESSF_BASE_URL}/courses/{code}` |
| курс + слова про файлы (syllabus, midterm, final, mock, экзамен, материалы) | `{PRESSF_BASE_URL}/courses/{code}#files` |
| преподаватель | `{PRESSF_BASE_URL}/professors/{id}` |
| группа + вопрос про расписание | `{PRESSF_BASE_URL}/timetable?class={class}` |
| программа + курикулум | `{PRESSF_BASE_URL}/programs/{slug}/curriculum` |

`code`, `id`, `class`, `slug` те же, что в API. Значения кодируются в URL.

### Где показывать

- **Шаги 3a, 3b, 3c** (расписание, человек, сайт университета): ссылка отдельной
  строкой или кнопкой под ответом автору.
- **Шаг 5** (публикация): ссылка в подтверждении автору. Пост в канале не меняется:
  он копируется как есть, и ссылок в канал бот не добавляет.
- **Дедуп** (`DUPLICATE`, `POSSIBLE`): ссылка рядом с найденным постом, если совпадение
  есть. Логика развилки «у меня другое» не меняется.
- Вопросы, которые не прошли фильтр или ушли на модерацию, ссылку не получают.
- Отключённый `TIMETABLE_ANSWER` ответы по расписанию не включает, но подсказка со
  ссылкой на расписание группы работает и без него. Если это мешает вашей логике, напишите.

### Правила сопоставления

- Только готовые `find_code`, `find_subject`, `find_person`, тем же сравнением и с
  теми же отсечками (`_COMMON_TOKEN`). Без векторного поиска и без LLM: неверная
  ссылка хуже её отсутствия.
- Ссылка только на сущность, которая есть в справочнике бота: нет записи, нет ссылки.
- Несколько совпадений: одна лучшая ссылка, в порядке код, название курса,
  преподаватель. Несколько равных кандидатов: ссылки нет.
- Подсказка не должна задерживать ответ и не должна ронять его: ошибка сборки ссылки
  означает ответ без ссылки.

### Приватность

В ссылке только публичные идентификаторы сущности. Никаких параметров отслеживания,
id автора, текста вопроса и хешей от них: это сохраняет правило «нет связи автор →
текст». На стороне бота считаем только агрегат, например `pressf_linked` в статистике
и карточках мод-группы, чтобы видеть качество совпадений.

### Текст

Короткая строка в `texts.py`, в стиле остальных ответов бота, на тех же языках.
Смысл: «Об этом курсе на Press F: кто ведёт, файлы, что пишут». Формулировки на ваше
усмотрение, Telegram-разметку и превью ссылок настройте так, чтобы подсказка не
перебивала основной ответ.

## Чего не надо

- Записи. Оценки, группа пользователя и всё пользовательское хранит сайт.
- Файлов. Студенты присылают их в отдельного Telegram-бота сайта, `anonymous` здесь
  не участвует.
- Данных о пользователях бота в любом виде.

## Принятые решения

- **Комментарии не сохраняем и не смотрим.** `/api/mentions` работает только по постам
  канала, отдельная таблица под комментарии не нужна.
- **Посты показываем и на странице преподавателя.** Фильтр `?teacher=` обязателен.
- **Домен сайта:** `https://pressf.chebarash.uz`. Сайт пишется заново, старые страницы
  и старая схема базы не учитываются, поэтому совместимость с ними не нужна.

## Что считаем готовым

- Все эндпоинты P0 и P1 отвечают по токену и отдают `401` без него.
- Каждый `teacher` в `/api/courses` и `/api/timetable` находится в `/api/faculty`.
- Код курса в `/api/timetable`, `/api/courses` и курикулуме нормализован одинаково.
- Для каждого потока из `/api/timetable` есть запись в `/api/groups`.
- Есть проверка на реальных данных в духе `scripts/check_*.py`, которая печатает:
  сколько преподавателей без записи, сколько курсов без кода, сколько потоков без
  программы, для скольких программ есть курикулум.
- С пустым `PRESSF_BASE_URL` поведение бота не меняется ни в одном шаге конвейера.
- С заданным `PRESSF_BASE_URL` тесты покрывают каждую строку таблицы ссылок и случаи
  «нет совпадения» и «несколько равных кандидатов». Батарея в духе
  `scripts/check_history.py` по реальной истории канала показывает долю вопросов со
  ссылкой и примеры, чтобы оценить ложные совпадения до включения на проде.
- Контракт и схема ссылок переехали в документацию бота, раздел «Внешний API».
